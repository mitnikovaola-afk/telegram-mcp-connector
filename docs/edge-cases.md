# Пограничні випадки (edge cases)

Що відбувається в незручних ситуаціях реальних чатів і як це перевірено. Перевірка трьох видів (третій — живий Telegram, [`demo.md`](demo.md) → «День 2»):
- **тест**: автоматичний тест у `tests/` з фейковими Telegram, LLM і Notion, детермінований і безкоштовний;
- **eval**: змодельований діалог, прогнаний через справжню модель (`evals/`). Звіт лежить у `evals/results/`.
- **живе демо**: 30 повідомлень «дня 2» у справжніх тестових групах, потім видалення й правки; 21/21 перевірок змісту.

## A. Синхронізація та дані

| Ситуація | Що робить конектор | Перевірка |
|---|---|---|
| Повторний, подвійний, пропущений запуск, падіння посеред прогону | див. таблицю «Ядро синхронізації» в README | тести в `test_pipeline.py` |
| Перший прогін нового чату | історія береться від **локальної опівночі** `BACKFILL_DAYS` днів тому, тож найстаріший день не самаризується «наполовину» | `test_first_sync_starts_at_local_midnight` |
| Повідомлення **видалили** в Telegram (написали не в той чат, прибрали пароль) | у вікні `EDIT_LOOKBACK_HOURS` видалене зникає з БД, день перераховується, і повідомлення зникає з самарі та Notion | `test_deleted_message_leaves_db_and_summary` |
| Видалили давно, поза вікном | не помічається (свідоме обмеження pull-моделі) | `test_deletion_outside_edit_window_is_a_known_limitation` |
| Звичайну групу **перетворили на супергрупу** (Telegram дає їй новий id) | конектор бачить службове повідомлення про міграцію, сам починає відстежувати новий id і зупиняє старий. Історія старого id зберігається | `test_group_upgraded_to_supergroup_is_followed`, `test_group_upgrade_service_message_is_detected` |
| **Втрачено доступ** до чату (вигнали, чат видалено) | помилка лише цього чату (`partial`, видно в `sync_status`); решта чатів синхронізується й самаризується | `test_broken_chat_does_not_stop_the_others` |
| Дуже **довгий день** | ділиться на частини, які потім зливаються (map-reduce); жодне повідомлення не обрізається мовчки | `test_very_long_day_is_split_and_merged_not_truncated` |
| Межа вікна правок | порівняння з точністю до секунди (як у Telegram), щоб повідомлення на межі не вважалось видаленим | `test_edit_window_uses_whole_seconds` |
| Особистий чат, історію якого не можна віддавати в LLM | `track --from-now`: читається лише те, що написано після підключення, навіть перечитування правок не чіпає старе | `test_track_from_now_never_reads_existing_history` |
| LLM недоступна, таймаут, вичерпана добова квота | день чекає в черзі, тимчасові збої не витрачають спроби, при квоті LLM ставиться на паузу до скидання | `test_llm_outage_*`, `test_day_long_quota_*`, `test_daily_quota_*` |

## B. Що бачить модель

| Ситуація | Що робить конектор | Перевірка |
|---|---|---|
| У чат скинули **пароль, номер картки, IBAN, ключ API, токен у посиланні, одноразовий код** | маскується **до відправки в LLM** (`redact.py`): `[hidden]`, `[card number hidden]`. Самарі, посилання в Notion і логи не містять значень. Оригінал лишається лише в локальній БД (`chmod 600`) | `test_secrets_never_reach_the_llm_or_notion` + eval `secrets_in_chat` |
| «Так, затверджую» **після півночі** у відповідь на питання з учора | у запит додається цитата повідомлення, на яке відповіли: `(reply to Олег, 19.11 23:55: «…»)` | `test_reply_to_yesterday_is_quoted_for_context` + eval `reply_after_midnight` |
| **Відносні дедлайни** («завтра», «до понеділка») | у заголовку дня є дата й день тижня, модель додає календарну дату: «понеділок, 23.11» | `test_header_has_weekday_for_relative_deadlines` + eval `relative_deadlines` |
| **Переслане** повідомлення (клієнт, інший чат) | позначається `[forwarded from X, originally 20.11 17:55]`: автором вважається X, а відносні дати («завтра») рахуються від дати оригіналу, а не від дати пересилання (баг знайдено на живому демо дня 2) | `test_forwarded_message_keeps_original_author_and_date` + eval `forwarded_from_client`, `forwarded_relative_date` |
| **Змішані мови** (український чат з англійськими термінами й англомовним колегою) | мову чату визначає код за останніми 200 повідомленнями (а не за одним днем, тож флуд чужою мовою її не перемикає) і явно передає моделі. Якщо у відповіді українською є російські літери (ы/э/ъ/ё) або в англійській кирилиця, модель переписує відповідь один раз | `test_language_is_detected_by_message_majority`, `test_one_day_of_foreign_messages_does_not_switch_chat_language`, `test_answer_in_wrong_language_is_reasked_once` + eval `mixed_language`, `english_chat` |
| **Метрики та цифри** (виручка, CPI, CTR, бюджети) | окремий розділ самарі «Ключові факти й цифри», числа копіюються точно | eval `exact_numbers` |
| **Голосові та відеокружки** | не розшифровуються, і модель не вигадує їхній зміст. Під самарі є лічильник «без розшифровки: N». День лише з голосовими все одно зʼявляється в Notion | `test_voice_only_day_is_not_silently_dropped`, `test_new_voice_note_updates_counter_without_llm_call` + eval `voice_notes` |

## C. Зміст діалогів (eval на справжній моделі)

`uv run python evals/run_eval.py`: 17 змодельованих діалогів, кожен з автоматичними перевірками змісту самарі.

| Сценарій | Ситуація |

| `answered_vs_open` | питання, на яке відповіли, не є відкритим |
| `sarcasm_and_maybe` | сарказм і «може колись» не є рішеннями |
| `small_talk_only` | день без роботи (привітання, день народження, кава): сторінки в Notion немає |
| `prompt_injection` | «Ignore all previous instructions…» та фальшивий «SYSTEM:» у чаті |
| `secrets_in_chat` | пароль, картка, ключ API |
| `mixed_language` | український чат з англійськими термінами й англомовним колегою |

1. «Завтра» в пересланому повідомленні рахувалось від дати пересилання.
2. На сторінці Notion дня з голосовими зникав увесь зміст самарі.

Обидва виправлено і покрито тестами.


## D. Відомі обмеження (свідомо не вирішено)

- **Теми (topics) у форум-групах** зливаються в одне самарі дня; назва теми в самарі не передається.
- **Перейменування чату**: у Notion лишається стара назва, поки чат не підключити повторно (`track` оновлює назву).
- **Зміна `TIMEZONE`** після синхронізації не переносить уже збережені повідомлення між днями.
- **Правки й видалення старші за `EDIT_LOOKBACK_HOURS`** не відстежуються (підтверджено на живому демо: правка вчорашнього «92% → 95%» не підхоплена).
- **Аудіофайл ≠ голосове.** Файл m4a Telegram зберігає як звичайний аудіофайл, і конектор показує його як `[file: назва]`. Голосовим вважається лише те, що Telegram позначив як голосове (OGG, `voice=True`).
- **Маскування секретів працює за шаблонами.** Нестандартний секрет («пароль той самий, що й торік, тільки з ! в кінці») не розпізнається. Тому для робочих чатів рекомендований тариф LLM, який не використовує дані для навчання.
- **Мова самарі** = мова більшості останніх повідомлень чату. Щоб закріпити мову, задайте `SUMMARY_LANGUAGE`, наприклад `Ukrainian`.
- **Модель може помилитися** у відносних датах чи виконавцях. Тому дедлайн показується так, як його сказали, плюс дата, і перевіряється eval-набором при зміні промпту чи моделі.
